// 基础概念

什么是功能安全？

🎯 一句话定义

功能安全就是：当系统出故障时，还能安全地工作或安全地停下来。

💡 举个栗子

电梯安全系统：当钢丝绳断裂时，安全钳自动夹住导轨，防止电梯坠落。

这就是功能安全——系统出故障了，但人还是安全的！

🛗
❌ 没有功能安全：钢丝绳断 → 电梯坠落 → 事故！
✅ 有功能安全：钢丝绳断 → 安全钳动作 → 电梯停住 → 人安全！

// 安全完整性等级

SIL等级：安全可靠性的"考试成绩"

SIL（Safety Integrity Level）就像考试分数，等级越高，安全功能越可靠

SIL 4

最高要求

PFD: 10⁻⁵~10⁻⁴
PFH: 10⁻⁹~10⁻⁸

🚨 核电、航天

SIL 3

高要求

PFD: 10⁻⁴~10⁻³
PFH: 10⁻⁸~10⁻⁷

🏭 化工、石油

SIL 2

中等要求

PFD: 10⁻³~10⁻²
PFH: 10⁻⁷~10⁻⁶

🛗 电梯、机械

SIL 1

基本要求

PFD: 10⁻²~10⁻¹
PFH: 10⁻⁶~10⁻⁵

🏠 家用电器

📊 PFD是什么？

平均故障概率，用于低要求模式（一年用不了几次）

📊 PFH是什么？

每小时故障概率，用于高要求模式（经常用或持续运行）

🔢 方法二：风险图法

考虑4个因素

C 后果严重程度 (C1~C4)
F 暴露频率 (F1~F2)
P 避免可能性 (P1~P2)
W 危险事件概率 (W1~W3)

根据C+F+P+W的组合，查表得到SIL等级

⚠️ 重要提示：SIL等级定得越高，开发成本越高，要合理确定！

// Part 2: E/E/PE系统要求

第2部分：硬件要求

针对电气/电子/可编程电子硬件系统的具体要求

🔧 硬件架构约束

HFT（硬件故障容错度）要求

SIL类型A类型B
SIL 4不允许HFT≥1
SIL 3HFT≥1HFT≥1
SIL 2HFT≥0HFT≥1
SIL 1HFT≥0HFT≥0

类型A：简单设备，故障模式明确
类型B：复杂设备，如CPU、FPGA

📊 安全失效分数(SFF)

SFF = (安全失效 + 检测到的危险失效) / 总失效

通俗理解：

  • SFF越高，说明大部分故障都能被检测到或不会导致危险
  • SFF≥90%，才能达到较高SIL等级

设计原则：通过冗余设计和故障检测提高安全性

由安全相关系统实现的、以达到或保持EUC安全状态为目的的功能。

安全相关系统在规定条件下和规定时间内成功实现要求的安全功能的概率。

// Part 5: SIL确定方法

第5部分：如何确定SIL等级

提供了多种确定安全完整性等级的实用方法

📊 方法一：风险图法

考虑因素：

C 后果：C1(轻微) ~ C4(多人死亡)
F 频率：F1(罕见) ~ F2(频繁)
P 避免：P1(可能) ~ P2(不可能)
W 概率：W1(很低) ~ W3(较高)

根据组合查表得到SIL

📐 方法二：定量计算

计算步骤：

  1. 确定原始风险R₀
  2. 确定可容忍风险Rt
  3. 计算风险降低因子RRF = R₀/Rt
  4. 根据RRF查表得到SIL
RRF ≥ 10000 → SIL 4
RRF ≥ 1000 → SIL 3
RRF ≥ 100 → SIL 2
RRF ≥ 10 → SIL 1

实用技巧：对于简单系统用风险图法，复杂系统用定量计算，两种方法交叉验证更可靠！

// FAQ

常见问题解答

Q1: 软件能通过冗余提高SIL吗？
不能！软件是系统性故障，冗余无法解决问题。两个相同软件的Bug也是一样的。必须通过开发过程质量保证。
Q2: 功能安全认证是强制的吗？
法律上不强制，但很多行业（汽车、化工、轨道交通）的市场准入要求认证。建议按标准做，不一定要认证。
Q3: SIL等级越高越好吗？
不是！SIL越高，成本越高。要根据实际风险确定，够用就行，过度设计是浪费。
Q4: 如何开始学习这个标准？
建议顺序：第1部分(框架) → 第4部分(术语) → 第5部分(SIL方法) → 第2/3部分(硬件/软件)
Q5: 敏捷开发能做功能安全吗？
可以！采用"敏捷+V模型"混合，将安全活动嵌入迭代周期，保持必要的文档和追溯。

💡 提示：标准是工具，不是目的。理解原理比死记条文更重要！
