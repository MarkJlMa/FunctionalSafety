// 定义

什么是功能安全？

功能安全是指通过正确实现安全功能来避免或控制系统性故障和随机硬件故障，从而使系统在可接受的风险水平下运行。

🎯 核心关注点

系统在故障情况下的安全性，而非正常功能的正确性

⚠️ 防止什么

  • 系统性故障（设计缺陷、软件Bug）
  • 随机硬件故障（元件老化、损坏）

💡 关键目标

当系统发生故障时，能够安全地进入或保持在安全状态

功能安全基础

// 对比

功能安全 ≠ 传统安全 ≠ 信息安全

🛡️ 功能安全

防止系统故障导致的危害
关注：系统自身的可靠性
例：压力容器超压保护系统

⚙️ 传统安全

防止物理危害导致的伤害
关注：机械防护、防护设备
例：防护罩、急停按钮

🔐 信息安全

防止恶意攻击导致的危害
关注：数据保护、访问控制
例：防火墙、加密传输

🔑 关键区别

  • 功能安全关注的是"系统出故障时还能安全吗？"
  • 信息安全关注的是"系统能否抵御攻击？"
  • 两者需要协同考虑，现代系统中界限日益模糊

// 历史教训

血的教训：为什么需要功能安全？

Therac-25 放射治疗仪事故

1985-1987年 · 美国/加拿大

  • 原因：软件竞争条件导致过量辐射
  • 后果：6人严重辐射伤害，3人死亡
  • 教训：软件需要功能安全设计

阿里安5号火箭爆炸

1996年 · 法属圭亚那

  • 原因：软件溢出错误导致火箭自毁
  • 后果：价值5亿美元火箭和卫星损毁
  • 教训：电子系统需要功能安全设计

💡 核心启示

软件和电子系统没有"物理失效"的概念，但会有系统性故障，同样需要功能安全保障。

// Core Concepts

核心概念

01

安全功能

系统为达到或保持安全状态而执行的功能。例：紧急停车、超压保护

02

安全完整性

安全功能在规定条件下和规定时间内成功实现要求功能的概率

03

风险降低

通过安全相关系统将风险降低到可接受的水平

🎯 风险降低公式

残余风险 = 原始风险 − 风险降低

安全相关系统的目标是将风险降低到可容忍的水平

// Safety Integrity Level

安全完整性等级 (SIL)

衡量安全功能可靠性的指标，SIL 4最高，SIL 1最低

SIL 4

PFD: 10⁻⁵ ~ 10⁻⁴

PFH: 10⁻⁹ ~ 10⁻⁸

最高要求

SIL 3

PFD: 10⁻⁴ ~ 10⁻³

PFH: 10⁻⁸ ~ 10⁻⁷

高要求

SIL 2

PFD: 10⁻³ ~ 10⁻²

PFH: 10⁻⁷ ~ 10⁻⁶

中等要求

SIL 1

PFD: 10⁻² ~ 10⁻¹

PFH: 10⁻⁶ ~ 10⁻⁵

基本要求

PFD - 平均故障概率

适用于低要求模式（每年最多调用一次）

PFH - 每小时危险故障概率

适用于高要求/连续模式（频繁或持续运行）

SIL等级

// SIL Determination

如何确定SIL等级？

📊 风险矩阵法

严重程度 vs 发生概率

极高风险→ SIL 3/4
高风险→ SIL 2/3
中风险→ SIL 1/2
低风险→ 无需SIL

🔢 定量风险评估

计算风险降低因子RRF

RRF = R₀ / Rtolerable
R₀: 无保护时的风险率
Rtolerable: 可容忍风险率

RRF ≥ 10000 → SIL 4

RRF ≥ 1000 → SIL 3

RRF ≥ 100 → SIL 2

RRF ≥ 10 → SIL 1

// Examples

SIL等级应用示例

SIL 3

工业压力容器保护系统

  • 后果：爆炸可能导致多人死亡
  • 暴露频率：工人经常在附近
  • 避免可能性：爆炸突然，难以避免
SIL 2

电梯门安全系统

  • 后果：可能导致重伤
  • 暴露频率：每天多次使用
  • 避免可能性：用户可能注意到并避免
SIL 1

家用燃气灶熄火保护

  • 后果：可能导致火灾或中毒
  • 暴露频率：每天使用
  • 避免可能性：用户可能闻到气味

关键原则：SIL等级越高，安全功能需要达到的可靠性越高，开发和验证要求也越严格。

// Hardware Requirements

硬件安全要求

硬件架构约束 (HFT)

HFT = 硬件故障容错度

SIL类型A类型B
SIL 4不允许HFT ≥ 1
SIL 3HFT ≥ 1HFT ≥ 1
SIL 2HFT ≥ 0HFT ≥ 1
SIL 1HFT ≥ 0HFT ≥ 0

类型A: 故障模式明确
类型B: 故障模式不明确(如复杂IC)

安全失效分数 (SFF)

SFF = (λS + λDD) / (λS + λDD + λDU)
  • λS: 安全失效率
  • λDD: 检测到的危险失效率
  • λDU: 未检测到的危险失效率
SIL 3HFT=0需SFF≥99%
SIL 2HFT=0需SFF≥90%

// FAQ

常见问题解答

Q1: 功能安全和质量管理有什么区别？
功能安全关注系统故障情况下的安全性，质量管理关注产品整体质量。功能安全需要更严格的风险分析和验证。
Q2: 如何确定系统需要达到哪个SIL等级？
通过风险评估确定，考虑危害后果严重程度、暴露频率、避免可能性等因素。可使用风险矩阵或定量方法。
Q3: 软件可以通过冗余提高SIL等级吗？
不能。软件是类型B系统，只能通过开发过程保证质量，冗余无法消除系统性故障。
Q4: 如何在敏捷开发中实施功能安全？
采用"敏捷+V模型"混合方式，将安全活动嵌入迭代周期，使用自动化工具提高效率，保持必要的文档和追溯。
Q5: 功能安全认证是强制的吗？
法律上不强制，但很多行业标准（如汽车ISO 26262）要求认证，市场准入也可能要求。

// Summary

总结与要点回顾

🎯 核心理解

  • 功能安全关注故障下的安全
  • IEC 61508是基础性标准
  • SIL等级衡量安全可靠性

✅ 实施要点

  • 遵循安全生命周期
  • 硬件关注架构约束和SFF
  • 软件关注开发过程质量

⚠️ 注意事项

  • 软件不能通过冗余提高SIL
  • 与网络安全协同考虑
  • 认证非强制但行业常要求
